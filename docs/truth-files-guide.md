# 长篇真相文件使用说明

真相文件不是章节正文，也不是普通备忘录。它是给长篇小说用的“长期事实库”：把后文不能写崩的事实、秘密、资源、关系变化和时间锚点单独记录下来，让生成大纲、写章节、审校和修订时都能参考。

一句话理解：

> 伏笔记录“读者会看到什么线索”，真相文件记录“作者心里已经确定的底层事实”。

## 什么时候需要真相文件

适合放进真相文件的内容通常有这些特征：

- 不是马上写进正文，但会影响很多章。
- 不能被后文随便改掉。
- 读者现在未必知道，但作者必须知道。
- 和人物关系、资源数量、隐藏身份、时间顺序、世界规则有关。
- 一旦写错，后面会出现大面积矛盾。

不适合放进真相文件的内容：

- 某一章的具体描写。
- 临时灵感句子。
- 已经能放进“世界观设定”的普通背景。
- 只需要追踪是否回收的读者可见线索，这类更适合“伏笔/支线”。

## 和其他资料的区别

| 功能 | 主要记录 | 用途 |
| --- | --- | --- |
| 世界观设定 | 城市、组织、规则、地点、能力体系 | 给模型理解作品背景 |
| 角色 | 人设、动机、关系、弧光 | 约束角色行为 |
| 伏笔/支线 | 读者能看到的线索、支线、回收计划 | 追踪是否推进/回收 |
| 拆书参考 | 导入别的文本或自己的旧稿 | 分析文风、设定、时间线，不计入正文 |
| 真相文件 | 作者视角的长期事实和隐藏约束 | 防止长篇连载写崩 |

例子：

- “主角左手会痛”是读者可见线索，放伏笔。
- “左手痛其实是旧神契约，每次用剑都会减少寿命”是底层真相，放真相文件。

## 类型怎么选

### 硬约束

用于不能违反的世界规则、能力限制、身份限制。

适合写：

- 主角不能在第 3 卷前主动打开天门。
- 灵管局不能直接杀普通人，只能记忆清除。
- 剑意不能治疗伤口，只能斩断异化。

### 资源账本

用于道具、资金、人情、寿命、势力资源、次数限制。

适合写：

- 主角目前只剩 3 次完整出剑机会。
- 林知微欠主角一次救命人情，但不能公开承认。
- 校内避难点还有 127 人，食物只能撑 2 天。

### 关系弧

用于长期关系变化，不只是“谁喜欢谁”，还包括信任、误解、背叛、阵营变化。

适合写：

- 嘉豪和林知微第 2 卷前互相利用，第 3 卷才真正信任。
- 同桌表面背叛，实际在保护妹妹。
- 灵管局局长不能完全信任主角，但会逐步放权。

### 隐藏真相

用于作者知道、读者暂时不知道的秘密。

适合写：

- 天门不是异界入侵通道，而是人类旧文明留下的封印口。
- 主角的剑意来自未来的自己。
- 反派组织真正目标不是毁城，而是逼主角觉醒。

### 时间锚点

用于必须按顺序发生的事件、倒计时、时间差。

适合写：

- 七日倒计时从运动会当天 16:20 开始。
- 地铁阵眼必须在第 2 卷第 5 章前第一次出现。
- 第 4 卷之前不能揭露旧城断剑的完整来源。

## 字段怎么填

| 字段 | 建议写法 |
| --- | --- |
| 类型 | 选择最接近的用途；不确定时选“硬约束” |
| 状态 | 生效中：会注入生成；草稿：想法未定；已完成：已经兑现；已归档：不再参与检查和生成 |
| 标题 | 写成一句可识别的短名，例如“主角真实寿命代价” |
| 范围 | 写“全书”“第 2 卷”“林知微关系线”“地铁阵眼线”等 |
| 负责人/相关人 | 写角色、组织、道具、地点或势力 |
| 内容 | 写清事实、限制、何时能揭露、不能怎么写 |

内容建议包含 3 件事：

1. 已确定事实是什么。
2. 什么时候之前不能揭露或改变。
3. 如果正文涉及它，必须遵守什么限制。

## 推荐模板

### 隐藏真相模板

```text
事实：主角的剑意来自未来的自己，不是祖传天赋。
限制：第 4 卷前不能明说“未来主角”，只能用梦境、断剑回声、似曾相识暗示。
影响：任何解释主角能力来源的章节，都不能写成普通血脉觉醒。
```

### 资源账本模板

```text
事实：完整封门剑只能使用 3 次，运动会已用掉 1 次。
限制：第 2 次必须留给地铁阵眼，第 3 次留到第 3 卷结尾。
影响：中途战斗不能随便让主角用完整封门剑解决问题。
```

### 关系弧模板

```text
事实：林知微前期接近嘉豪是任务安排，不是完全自愿。
限制：第 2 卷前她不能主动坦白；第 3 卷才从利用转向真正信任。
影响：她可以保护嘉豪，但对白里不能过早表露完全信任。
```

## 它会影响哪些功能

真相文件会参与：

- 生成整书/分卷/章节大纲。
- 生成章节正文。
- 重新审校章节。
- 自动修订和去 AI 味修订。
- 章节上下文预览。
- 真相文件一致性检查。
- Markdown / EPUB 导出中的作品资料部分。

真相文件不会做这些事：

- 不会自动变成正文。
- 不会把内容原封不动写进章节。
- 不会替代伏笔/支线追踪。
- 不会自动修改已有章节，除非后续你明确应用某个维护动作。

## 一致性检查怎么看

“检查矛盾”会扫描非归档真相文件、设定、角色和正文卷章，返回三类信息：

- 问题：哪里可能写崩了。
- 证据：模型根据哪段资料判断。
- 维护建议：下一步该改真相文件、改章节、改设定，还是调整状态。

如果维护建议是“更新状态”，界面会提供“应用状态”。你也可以勾选多条状态建议后批量应用。它只会改真相文件状态，不会自动改正文；应用后会留下最近处理记录，方便回看哪些建议已经处理过。

## 一个完整例子

标题：封门剑次数限制

类型：资源账本

状态：生效中

范围：全书

负责人/相关人：嘉豪 / 断剑

内容：

```text
事实：嘉豪完整使用封门剑的机会只有 3 次，运动会结尾已消耗 1 次。
限制：第 2 次必须用于第 2 卷地铁阵眼，第 3 次留到第 3 卷结尾。
影响：第 2 卷前半段不能让嘉豪靠完整封门剑轻松解决大型敌人，只能使用残缺剑意或借助环境。
```

这个例子会帮助模型避免：

- 每次打不过就让主角开大。
- 章节之间忘记已经用过一次。
- 审校时漏掉资源消耗矛盾。

## 最简单的使用方式

如果不知道怎么开始，只要先建 3 条：

1. 主角能力最大的限制。
2. 一个暂时不能公开的核心秘密。
3. 一条重要关系的真实走向。

后面每写出新的底层事实，再慢慢补。不要一开始就把所有内容都塞进去。真相文件的价值在于稳定长篇，不在于数量多。
